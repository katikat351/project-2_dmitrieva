# primitive_db

Учебный проект: консольная база данных на Python. Поддерживает создание и удаление таблиц, CRUD-операции, хранение данных в JSON-файлах, подтверждение опасных действий и кэширование запросов `select`.

## Установка

Требуется Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```
git clone https://github.com/katikat351/project-2_dmitrieva
cd project-2_dmitrieva
make install
```

Без `make`: `uv sync`.

## Запуск

```
make run
```

Без `make`: `uv run database`. Установленный пакет (`uv tool install .`) запускается командой `database`.

## Проверка кода

```
make lint
```

Без `make`: `uv run ruff check .`.

## Управление таблицами

Команды:

- `create_table <имя_таблицы> <столбец1:тип> <столбец2:тип> ...` — создать таблицу (столбец `ID:int` добавляется автоматически);
- `list_tables` — показать список всех таблиц;
- `drop_table <имя_таблицы>` — удалить таблицу;
- `help` — справочная информация;
- `exit` — выход из программы.

Поддерживаемые типы данных: `int`, `str`, `bool`.

Пример:

```
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

>>>Введите команду: list_tables
- users

>>>Введите команду: drop_table users
Таблица "users" успешно удалена.
```

Информация о таблицах хранится в файле `db_meta.json`.

## CRUD-операции

Данные каждой таблицы хранятся в отдельном файле `data/<имя_таблицы>.json`.

Команды:

- `insert into <имя_таблицы> values (<значение1>, <значение2>, ...)` — создать запись;
- `select from <имя_таблицы>` — прочитать все записи;
- `select from <имя_таблицы> where <столбец> = <значение>` — прочитать записи по условию;
- `update <имя_таблицы> set <столбец> = <новое_значение> where <столбец> = <значение>` — обновить записи;
- `delete from <имя_таблицы> where <столбец> = <значение>` — удалить записи;
- `info <имя_таблицы>` — вывести информацию о таблице.

Правила:

- значения для `ID` не передаются, он генерируется автоматически;
- все поля обязательны, число значений должно совпадать с числом столбцов (без `ID`);
- строки пишутся в кавычках: `"Sergei"`;
- логические значения: `true` и `false`;
- типы значений проверяются по схеме таблицы.

Пример:

```
>>>Введите команду: insert into users values ("Sergei", 28, true)
Запись с ID=1 успешно добавлена в таблицу "users".

>>>Введите команду: select from users where age = 28
+----+--------+-----+-----------+
| ID |  name  | age | is_active |
+----+--------+-----+-----------+
| 1  | Sergei | 28  |    True   |
+----+--------+-----+-----------+

>>>Введите команду: update users set age = 29 where name = "Sergei"
Запись с ID=1 в таблице "users" успешно обновлена.

>>>Введите команду: delete from users where ID = 1
Запись с ID=1 успешно удалена из таблицы "users".

>>>Введите команду: info users
Таблица: users
Столбцы: ID:int, name:str, age:int, is_active:bool
Количество записей: 0
```

## Обработка ошибок, подтверждение действий и кэш

### Обработка ошибок

Ошибки ввода и работы с данными не приводят к падению программы: вместо этого выводится понятное сообщение, и можно вводить следующую команду. Например:

```
>>>Введите команду: insert into users values ("Ivan", "abc", true)
Ошибка валидации: Неверный тип значения для "age": ожидается int.

>>>Введите команду: select from nothing
Ошибка валидации: Таблица "nothing" не существует.
```

### Подтверждение опасных операций

Перед удалением таблицы (`drop_table`) и записей (`delete`) программа запрашивает подтверждение. Если ответ не `y`, операция отменяется:

```
>>>Введите команду: delete from users where ID = 2
Вы уверены, что хотите выполнить "удаление записей"? [y/n]: n
Операция отменена.

>>>Введите команду: delete from users where ID = 2
Вы уверены, что хотите выполнить "удаление записей"? [y/n]: y
Запись с ID=2 успешно удалена из таблицы "users".
```

При удалении таблицы вместе с ней удаляется и файл с её данными `data/<имя_таблицы>.json`.

### Время выполнения

Для операций `insert` и `select` выводится время выполнения:

```
Функция insert выполнилась за 0.000 секунд.
```

### Кэширование select

Результаты одинаковых запросов `select` кэшируются: повторный запрос берёт данные из кэша и не читает файл заново. Кэш сбрасывается после любого изменения данных (`insert`, `update`, `delete`) и при удалении таблицы, поэтому результаты всегда актуальны.
